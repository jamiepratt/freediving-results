# Private source bundle for the 2026-09-28 owner snapshot

`scripts/private_source_bundle.py` builds, verifies, and restores a private content-addressed bundle from an inventory JSON file. Keep the inventory and bundle outside Git, the public release, and the active worker. The inventory supplies an `id`, expected SHA-256, byte length when known, content type, local original path, safe acquisition receipt, source references, and one disposition per source. `build` checks eligible originals before copying. `verify` hashes every included object; `restore` copies and verifies into a new directory. Bundle directories and files use modes 0700 and 0600.

```sh
python3 scripts/private_source_bundle.py build --inventory <private-inventory.json> --bundle-dir <private-bundle>
python3 scripts/private_source_bundle.py verify --bundle-dir <private-bundle>
python3 scripts/private_source_bundle.py restore --bundle-dir <private-bundle> --output-dir <independent-restore>
```

The inventory must be derived from `snapshot.sqlite` and its `manifest.json`, not a count of displayed rows. In this snapshot, `records` with `source_name='baseline' AND collection='sources'` contain 105 distinct original SHA-256 values and acquisition receipts. The seven completed FIPSAS packet namespaces cite hashes already in that set. The GIA metadata supplies one individual workbook source plus a separate excluded club aggregate workbook. The two retained-only artifact receipts cite hashes already in the baseline. Include `snapshot.sqlite` and its manifest as two separate verified bundle objects. Keep `source_name` namespaces distinct; a common byte hash does not establish that source positions or sporting attempts are the same.

## Source-view lookup contract

After owner authentication, use a snapshot record's `source_object_id` only when it is an exact `sha256:<64 lowercase hex>` identifier. Find that identifier in the bundle manifest, require `status=included` for an original-byte view, verify the object hash and byte count, then render according to its recorded content type with the record's citation. For PDF, use the cited page and region when present; for JSON, show the retained response beside the exact raw and parsed record fields. A restricted Vestico source may instead expose only its separately verified, record-bound safe derivative row. Never accept a client file path or arbitrary URL as an object lookup. A manifest status of `missing`, `restricted`, or `excluded` never offers an original-byte link. The original audit matched all 105 baseline source IDs and all 96 distinct non-null record `source_object_id` values to manifest entries; matching an entry does not mean its bytes are included.

GIA rows in this snapshot have no `source_object_id`; their workbook hash exists only in the `gia` namespace metadata. The present data cannot assert a per-row immutable object binding, so the UI must show the workbook-level receipt and an unresolved row-binding gap. Other packet namespaces retain their own source IDs and row citations; equal hashes across namespaces do not authorize row equality. The authenticated read-only origin serves bounded cited PDF/JSON originals from the pinned private bundle; its private route has not been activated remotely.

The bundle is a partial portable backup of this dated snapshot, not a complete backup of the worker archive or PostgreSQL corpus. Offline parser replay is available only where the included bytes and selected-view evidence suffice. It remains unavailable for the missing and restricted originals, and no corrected observation or source relationship is inferred by this bundle.
