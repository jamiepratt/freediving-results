# Private source bundle for the 2026-09-28 owner snapshot

`scripts/private_source_bundle.py` builds, verifies, and restores a private content-addressed bundle from an inventory JSON file. Keep the inventory and bundle outside Git, the public release, and the active worker. The inventory supplies an `id`, expected SHA-256, byte length when known, content type, local original path, safe acquisition receipt, source references, and one disposition per source. `build` checks eligible originals before copying. `verify` hashes every included object; `restore` copies and verifies into a new directory. Bundle directories and files use modes 0700 and 0600.

```sh
python3 scripts/private_source_bundle.py build --inventory <private-inventory.json> --bundle-dir <private-bundle>
python3 scripts/private_source_bundle.py verify --bundle-dir <private-bundle>
python3 scripts/private_source_bundle.py restore --bundle-dir <private-bundle> --output-dir <independent-restore>
```

The inventory must be derived from `snapshot.sqlite` and its `manifest.json`, not a count of displayed rows. In this snapshot, `records` with `source_name='baseline' AND collection='sources'` contain 105 distinct original SHA-256 values and acquisition receipts. The seven completed FIPSAS packet namespaces cite hashes already in that set. The GIA metadata supplies one individual workbook source plus a separate excluded club aggregate workbook. The two retained-only artifact receipts cite hashes already in the baseline. Include `snapshot.sqlite` and its manifest as two separate verified bundle objects. Keep `source_name` namespaces distinct; a common byte hash does not establish that source positions or sporting attempts are the same.
