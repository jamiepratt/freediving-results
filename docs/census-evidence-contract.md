# Private census evidence contract

`scripts/census_contract.py` validates and queries `census-evidence/v1` JSON snapshots for the owner evidence workspace in [issue #54](https://github.com/jamiepratt/freediving-results/issues/54). A snapshot has a dated scope and separate event, source, source-position, discovery-gap and relationship records. Source records retain original-byte hashes, acquisition and URL provenance, authority type, and selected-view state where applicable. Position records retain a source locator, printed raw fields or an explicit unresolved reason, and exact observation-version references. Relationships require a cited basis and an explicit evidence state. The summary always reports confirmed distinct sporting attempts as `null`; source positions and observation versions are separate counts.

Run `python3 scripts/census_contract.py validate SNAPSHOT.json` to check a private snapshot, or `python3 scripts/census_contract.py query --event EVENT_ID --source SOURCE_ID --status parsed SNAPSHOT.json` to select records. Query output retains gap and relationship records relevant to the selected positions. Neither command edits evidence or grants extraction validation, athlete identity approval, event selection or publication.

The 2026-09-28 baseline is privately retained in ignored `data/issue55-baseline-20260928/`. Its reproducible receipt has SHA-256 `360fc515fdd31e9c750b0c51e12092741b7d15e80cafb602288a76aba67b6ff6`; the three-position contract sample has SHA-256 `2ea2f682d00bbdeb904de26ab89b83dcf1217d2daca84d2ef58fd5e1e7127a36`. The 466-file worker bundle verified with index SHA-256 `cebc88ea6907170fa28058e1ba3e40f2c541938cf75047be08f5665ffa3d305c`. It is a bounded snapshot of retained evidence, not the complete 2025-2026 census. The worker and championship cohorts overlap and their source or row counts cannot be added into a unique-attempt total. The ongoing discovery and full row-level materialization remain tracked in [issue #55](https://github.com/jamiepratt/freediving-results/issues/55).

## Official discovery route roster

`scripts/issue55_route_roster.py` validates a private `issue55-route-roster/v1` JSON input and writes a deterministic, mode-0600 normalized roster for #55 and read-only #54 queries:

```sh
python3 scripts/issue55_route_roster.py PRIVATE_INPUT.json --output PRIVATE_ROSTER.json
```

The input has a UTC `cutoff`, `routes`, and `leads`. Each route has a stable `id`, `authority`, `role` (`primary`, `mirror`, `corroboration`), `discovery_url`, `status` (`checked`, `acquired`, `missing`, `inaccessible`, `unchecked`), `checked_at`, exact response `receipt` (`url`, `final_url`, `http_status`, `content_type`, `bytes`, `sha256`), `citation` (`url`, `sha256`, `locator`), and `gaps`. `checked_at` and `receipt` are null only for unchecked routes. An optional ordered `status_history` documents rechecks and access recovery. A lead has stable `id` and `route_id`, `title`, `url`, the same status vocabulary and exact citation, `competition_date` and optional `competition_date_to`, `competition_year`, cited `date_evidence`, nullable `session`, `discipline`, `category`, optional `event_key` and `candidate_event_keys`, `relationship` (`primary`, `mirror`, `corroboration`, `unknown`), proven `snapshot_ids`, uncertain `candidate_snapshot_ids`, `gaps`, and optional `status_history`. Date fields refer to **competition**, not page publication. When only the competition year is known, the date remains null; `date_evidence` defaults to the exact calendar citation when omitted. An exact date requires its own cited date evidence. Both year and date may remain null for an undated lead. `event_key` groups related source links without establishing attempt equivalence; `candidate_event_keys` records uncertain cross-route event links.

The validator rejects dates outside 2025-2026, malformed or mismatched receipts and citations, status-history regressions, and leads with unknown route IDs. It sorts records and evidence ID lists, then reports route and lead counts by status, lead counts by competition year and route, and `confirmed_distinct_attempts: null`. These are bounded discovery counts, not a claim that either federation calendar or the world census is complete. The roster cites hashes supplied in the private input; it does not fetch URLs, inspect source bytes, verify historical snapshot IDs, approve identities, or publish results. Original response bytes and HTTP receipts must remain separately retained in the private corpus.
